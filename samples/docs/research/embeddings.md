# 임베딩 정리

임베딩은 텍스트를 고정 길이의 숫자 벡터로 바꾼 것이다. 의미가 비슷한 문장은 벡터 공간에서 가깝게 놓인다.

## 유사도 계산

- **코사인 유사도**: 두 벡터 사이 각도로 비교한다. 가장 흔히 쓴다.
- **내적**: 정규화된 벡터라면 코사인 유사도와 같다.

## 저장소 후보

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 메모리 배열 | 구현이 가장 단순 | 문서가 많아지면 느림 |
| SQLite + 확장 | 파일 하나로 관리 | 확장 설치 필요 |
| 전용 벡터 DB | 대규모에 적합 | 운영 부담 |

샘플 문서 수준에서는 메모리 배열로 충분하다. 2단계 계획은 [[roadmap]]에 있다.

## 키워드 검색과의 관계

임베딩 검색은 동의어에 강하지만 고유명사나 정확한 숫자에는 약하다. 그래서 키워드 검색과 섞는 **하이브리드 검색**을 많이 쓴다. [[korean-search]] 참고.
